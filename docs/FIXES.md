# 🔧 Исправления проблем

## Проблема 1: Фото не распознаётся

### Симптом
При загрузке реального фото бот отвечает: "На фото не удалось обнаружить проблему"

### Причина
Веб-прототип не подключён к ML API напрямую. Когда пользователь загружает реальное фото, симуляция получает строку "загруженное фото", которая не совпадает ни с одним ключевым словом, поэтому возвращает `NOT_INCIDENT`.

### Решение
1. **Для реальных фото без текста** — показываем сообщение:
   ```
   📷 Фото получено! В демо-версии прототипа реальные фото не анализируются 
   ML-моделью. Чтобы продолжить, выберите тип проблемы или опишите её текстом.
   
   💡 В реальном боте MAX фото анализируется автоматически через ML API.
   ```

2. **Для фото + текст** — используем только текст для анализа (фото игнорируется в прототипе)

3. **Для демо-режима** — симуляция работает как раньше

### Где исправлено
- `src/components/ResidentChat.tsx` — добавлена проверка `hasFile && !text && !hasDemoImage`

## Проблема 2: Низкий процент тестов (9/17)

### Симптом
Тесты показывают 9 из 17 успешных

### Причина
1. **Тест t8 (Газ)** — "газ" не был в ключевых словах
2. **Тесты i1-i4 (IMAGE_ONLY)** — ожидали `KNOWN_INCIDENT`, но по новой логике fusion IMAGE_ONLY всегда возвращает `NEEDS_CLARIFICATION` (нет текста для определения подкатегории)

### Решение

#### 1. Добавлен "газ" в ключевые слова
```typescript
ELECTRICITY: [
  // ...
  { words: ['газ', 'пахнет газ'], subcategory: 'EXPOSED_WIRES' } // Газ — критическая ситуация
]
```

#### 2. Обновлены ожидаемые результаты для IMAGE_ONLY
```typescript
// Было:
{ id: 'i1', expectedResult: 'KNOWN_INCIDENT', expectedCategory: 'WATER_SUPPLY' }

// Стало:
{ id: 'i1', expectedResult: 'NEEDS_CLARIFICATION', expectedCategory: 'WATER_SUPPLY' }
```

**Почему NEEDS_CLARIFICATION?**
По новой логике fusion (API v2.1):
- IMAGE_ONLY → мы можем определить категорию (WATER_SUPPLY), но не подкатегорию (PIPE_LEAK или NO_WATER)
- Поэтому запрашиваем уточнение у пользователя

Это **правильная логика**! Без текста мы не можем точно определить подкатегорию.

### Где исправлено
- `src/data/aiEngine.ts` — добавлен "газ" в ELECTRICITY
- `src/components/TestScenarios.tsx` — обновлены ожидаемые результаты для i1-i4

## Важные изменения в логике

### IMAGE_ONLY всегда запрашивает уточнение
**Почему?**
- Фото даёт категорию (WATER_SUPPLY), но не подкатегорию (PIPE_LEAK vs NO_WATER)
- Нужно уточнение у пользователя для точной маршрутизации

**Пример:**
```
Пользователь: [фото протечки]
Бот: 📷 Фото получено! Опишите подробнее, что произошло?
Пользователь: Течёт труба в подвале
Бот: ✅ Мы поняли проблему так:
     📋 Водоснабжение
     📍 Протечка трубы
     ⚡ Высокий
     👷 Сантехник
```

### TEXT_AND_IMAGE использует fusion по top3
**Пример 1 (HIGH):**
- Фото: WATER_SUPPLY (0.88)
- Текст: WATER_SUPPLY/PIPE_LEAK (0.94)
- **Результат:** KNOWN_INCIDENT, fusion level = HIGH

**Пример 2 (MEDIUM):**
- Фото: ELECTRICITY (0.45), WATER_SUPPLY (0.38)
- Текст: WATER_SUPPLY/PIPE_LEAK (0.92)
- **Результат:** KNOWN_INCIDENT, fusion level = MEDIUM, needs_review = true

**Пример 3 (LOW):**
- Фото: ELECTRICITY (0.80)
- Текст: YARD/FALLEN_TREE (0.91)
- **Результат:** NEEDS_CLARIFICATION, запрашиваем уточнение

## Реальный бот vs Веб-прототип

### Веб-прототип (демо)
- Симуляция AI в браузере
- Реальные фото не анализируются (только демо-режим)
- Используется для демонстрации UX

### Реальный бот (MAX)
- Подключён к ML API (https://v3258578.hosted-by-vdsina.ru)
- Анализирует реальные фото через Vision API
- Анализирует текст через Text API
- Использует fusion по top3 (API v2.1)

**Важно:** Логика fusion одинаковая в обоих проектах!
