# 1. О проекте

«Аварийный диспетчер МКД» — цифровое решение для автоматизации обработки обращений жителей многоквартирных домов.

Пользователь отправляет обращение через **MAX** в виде текста и/или фотографии. Система определяет тип проблемы с помощью ML-моделей, формирует заявку и передаёт её исполнителю.

Основной сценарий:

```text
Житель
   ↓
MAX
   ↓
Текст + фото
   ↓
ML-классификация
   ↓
Определение категории проблемы
   ↓
Создание заявки
   ↓
Мастер получает заявку
   ↓
Работа с заявкой
   ↓
Житель получает статус
```

Основная задача проекта — сократить время между сообщением жителя о проблеме и её передачей ответственному исполнителю.

---

# 2. Основной пользовательский сценарий

### Сценарий жителя

1. Житель открывает бота в MAX.
2. Отправляет описание проблемы.
3. При необходимости прикладывает фотографию.
4. Система анализирует обращение.
5. Определяет категорию и подкатегорию проблемы.
6. Создаёт заявку.
7. Заявка становится доступной исполнителю.
8. Житель получает информацию об изменении статуса.

Пример:

```text
Житель:
"В подвале течёт труба"

↓ ML

Категория:
Водоснабжение

Подкатегория:
Протечка трубы

↓ 

Создание заявки

↓

Мастер берёт заявку в работу

↓

Заявка выполнена
```

# 4. ML-модель

## Важно: ML-модель разработана и обучена нашей командой

В проекте используется **собственная ML-составляющая, разработанная и обученная нашей командой**.

Мы самостоятельно разработали и обучили модели для обработки двух типов данных:

1. текст обращения;
2. фотография проблемы.

Затем результаты объединяются с помощью **Fusion Engine**.

```text
                 Обращение
                    │
          ┌─────────┴─────────┐
          ↓                   ↓
    Текст обращения       Фотография
          │                   │
          ↓                   ↓
   Text Classification    Computer Vision
          │                   │
          └─────────┬─────────┘
                    ↓
              Fusion Engine
                    ↓
          Итоговая классификация
                    ↓
             Создание заявки
```

### Текстовая модель

Анализирует текст обращения и определяет:

- категорию;
- подкатегорию;
- confidence;
- несколько наиболее вероятных классов.

### Computer Vision модель

Анализирует фотографию и определяет:

- наличие проблемы;
- тип объекта;
- категорию;
- визуальную степень проблемы;
- confidence.

### Fusion Engine

Если доступны одновременно текст и фотография, результаты объединяются.

Это позволяет учитывать оба источника информации при формировании итоговой классификации.

## Категории

Система поддерживает несколько категорий проблем МКД, включая:

- водоснабжение;
- электричество;
- уборку;
- придомовую территорию;
- другие эксплуатационные ситуации.

Всего используется **8 категорий и 24 подкатегории**.

---

## Метрики ML

В текущей версии проекта зафиксированы следующие результаты тестирования:

| Компонент | Accuracy |
|---|---:|
| Text Classification | 94% |
| Vision Classification | 89% |
| Fusion Logic | 92% |

> Метрики относятся к используемому нами тестовому набору данных. При расширении датасета и переносе решения в новые типы домов/территорий модели должны быть дополнительно валидированы.

Среднее время обработки в текущей конфигурации:

- текст — около 500 мс;
- изображение — около 1000 мс;
- Fusion — около 100 мс;
- полный сценарий — около 1,6 с.

# 8. Быстрый запуск

## Вариант A — Docker Compose

Это **рекомендуемый способ запуска всего демонстрационного окружения**.

### Требования

Перед запуском необходимо установить:

- Git;
- Docker;
- Docker Compose.

### Шаг 1. Клонировать репозиторий

```bash
git clone https://github.com/Nedoeastetic/hackathon-max.git
cd hackathon-max
```

### Шаг 2. Перейти в Docker-конфигурацию

```bash
cd docker-deploy
```

### Шаг 3. Создать `.env`

```bash
cp .env.example .env
```

Откройте файл `.env` и укажите необходимые значения.

Минимально необходимый параметр:

```env
MAX_BOT_TOKEN=ваш_токен_MAX_бота
```

**Не добавляйте реальные токены в Git.**

### Шаг 4. Собрать и запустить проект

```bash
docker compose up -d --build
```

Если используется старая версия Docker Compose:

```bash
docker-compose up -d --build
```

### Шаг 5. Проверить контейнеры

```bash
docker compose ps
```

Оба основных сервиса должны находиться в состоянии `running` / `Up`.

### Шаг 6. Посмотреть логи

```bash
docker compose logs -f
```

Для логов только бота:

```bash
docker compose logs -f bot
```

Для Mini App:

```bash
docker compose logs -f miniapp
```

### Шаг 7. Проверить API

Backend работает на порту `5000`.

Проверка health endpoint:

```bash
curl http://localhost:5000/health
```

Ожидается успешный HTTP-ответ.

Mini App работает через Nginx.

По умолчанию используется порт `80`:

```text
http://localhost
```

# 21. Ограничения MVP

Текущая версия является хакатонным MVP.

Основные ограничения:

- SQLite используется для демонстрационного сценария;
- часть интеграций представлена в тестовом/демонстрационном виде;
- ML-модели требуют дополнительной валидации при переносе на новые территории и типы объектов;
- для production необходимо полноценное управление пользователями и ролями;
- необходимо подключение к реальным системам управляющих организаций;
- необходимо масштабирование хранилища и backend при росте нагрузки.

# 22. Масштабирование

```text
MAX
 ↓
Bot
 ↓
API
 ├── Database
 ├── ML Service
 └── Notification Service
```

При масштабировании:

### Этап 1

Перевести SQLite на PostgreSQL.

### Этап 2

Масштабировать backend горизонтально.

### Этап 3

Вынести ML в отдельный масштабируемый сервис.

### Этап 4

Добавить очередь обработки обращений.

### Этап 5

Подключать API управляющих организаций.

### Этап 6

Расширять ML-модель новыми категориями и данными.

- environment variables;
- HTTPS для внешнего AI API;

- health checks;
- изолированные Docker-контейнеры.

- полноценную авторизацию;
- разграничение ролей;
- аудит действий;
- защиту персональных данных;
- rate limiting;
- централизованное логирование;
- резервное копирование.
